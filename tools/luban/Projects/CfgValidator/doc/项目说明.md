## 项目入口和执行机制

### 项目类型

**CfgValidator 是一个 MSTest 单元测试项目**，没有传统的 `Program.cs` 入口文件。

### 执行方式

项目通过 `dotnet test` 命令运行，可以从以下方式执行：

1. **命令行执行**：
   ```bash
   dotnet test -v m
   ```

2. **批处理脚本**：
   - 运行 `run_CfgValidator.bat` 脚本
   - 脚本会先执行 Luban 代码生成，然后运行测试

3. **Visual Studio / Rider**：
   - 通过 IDE 的测试运行器执行

## ConfigSetUp.Initialize 调用机制

### 代码位置

`ConfigSetUp.cs` 文件中的 `Initialize` 方法：

```csharp
[AssemblyInitialize]
public static void Initialize(TestContext testContext)
{
    LoadConfig();
}
```

### 调用流程

`Initialize` 方法**不是手动调用的**，而是由 **MSTest 测试框架自动调用**的。

#### 完整执行流程：

```
dotnet test
  ↓
MSTest 框架启动
  ↓
发现所有 [TestClass] 标记的类
  ↓
调用 [AssemblyInitialize] → ConfigSetUp.Initialize()
  ↓
  → LoadConfig() → 加载配置文件
  ↓
运行所有 [TestMethod] 标记的方法
  ↓
调用 [AssemblyCleanup] → ConfigSetUp.CleanUp()
```

### MSTest 初始化特性说明

| 特性 | 作用 | 执行时机 |
|------|------|----------|
| `[AssemblyInitialize]` | 程序集级别初始化 | 在所有测试运行之前执行**一次** |
| `[ClassInitialize]` | 类级别初始化 | 在类中所有测试运行之前执行**一次** |
| `[TestInitialize]` | 方法级别初始化 | 在每个测试方法执行前执行 |

### 重要说明

- ✅ `[AssemblyInitialize]` 会在所有测试类发现后、任何测试执行前自动调用
- ✅ 必须是 `public static` 方法
- ✅ 只能有一个 `[AssemblyInitialize]` 方法在程序集中
- ✅ 如果初始化失败，所有测试都不会执行

## LoadJson 方法说明

### 方法定义

```csharp
private static JsonElement LoadJson(string file)
{
    // 获取当前程序集所在目录，然后定位到 output_data 目录
    var assemblyLocation = System.Reflection.Assembly.GetExecutingAssembly().Location;
    var assemblyDir = Path.GetDirectoryName(assemblyLocation);
    
    // 从 bin/Debug/net8.0/ 返回到项目根目录（CfgValidator）
    var projectRoot = Path.GetFullPath(Path.Combine(assemblyDir, "..", "..", ".."));
    var configDir = Path.Combine(projectRoot, "output_data");
    
    var jsonPath = Path.Combine(configDir, file + ".json");
    
    if (!File.Exists(jsonPath))
    {
        throw new FileNotFoundException($"配置文件未找到: {jsonPath}。请确保已运行 Luban 生成配置数据。");
    }
    
    return JsonDocument.Parse(File.ReadAllBytes(jsonPath)).RootElement;
}
```

### 功能说明

1. **参数**：`file` - 配置文件名（不含扩展名），例如 `"demo_tbitem"`

2. **返回类型**：`JsonElement` - `System.Text.Json` 的 JSON 元素类型

3. **主要逻辑**：
   - 定位配置文件目录：从程序集位置（`bin/Debug/net8.0/`）上溯到项目根目录
   - 定位到 `output_data` 目录
   - 构建完整的 JSON 文件路径（添加 `.json` 扩展名）
   - 检查文件是否存在，不存在则抛出异常
   - 读取文件内容并解析为 `JsonElement` 返回

### 在 ConfigSetUp 中的使用

```csharp
public static void LoadConfig()
{
    Configs = new cfg.Tables(LoadJson);  // LoadJson 作为委托传入
}
```

**关键点**：
- `LoadJson` 作为**委托（方法引用）**传递给 `cfg.Tables` 构造函数
- `cfg.Tables` 会根据需要调用 `LoadJson` 来加载配置表
- 这是**策略模式**的一种实现：将数据加载逻辑从配置表类中解耦出来

### 使用示例

当 `cfg.Tables` 需要加载 `demo_tbitem` 配置表时：

1. 调用 `LoadJson("demo_tbitem")`
2. 方法会读取 `output_data/demo_tbitem.json`
3. 返回解析后的 `JsonElement`
4. `cfg.Tables` 使用这个 `JsonElement` 来构建配置对象

## MSTest 测试发现和执行机制

### 问题：CfgCheck.Modules.Test 类是如何被识别的？

### 答案：通过反射机制自动发现

MSTest 使用 **反射（Reflection）** 机制来自动发现和执行测试，无需手动注册。

### 测试发现过程（Test Discovery）

#### 步骤 1：扫描程序集

```
加载 CfgValidator.dll（编译后的程序集）
↓
使用反射（Reflection）扫描所有类型
```

#### 步骤 2：识别测试类

框架查找带有 `[TestClass]` 特性的类：

```csharp
[TestClass]  // ← 这个特性告诉 MSTest：这是一个测试类
public class Test
{
    // ...
}
```

**特性来源**：
- `[TestClass]` 来自 `Microsoft.VisualStudio.TestTools.UnitTesting`
- 已在 `Test.cs` 文件开头引用：
  ```csharp
  using Microsoft.VisualStudio.TestTools.UnitTesting;
  ```

#### 步骤 3：识别测试方法

在每个测试类中，查找带有 `[TestMethod]` 特性的方法：

```csharp
[TestMethod]  // ← 这个特性告诉 MSTest：这是一个测试方法
public void Check_X1_X2_LengthMatch()
{
    // 测试逻辑
}
```

### 完整执行流程

### 反射机制示例（伪代码）

MSTest 内部大致是这样的逻辑：

```csharp
// 伪代码，展示 MSTest 如何发现测试
var assembly = Assembly.LoadFrom("CfgValidator.dll");
var types = assembly.GetTypes();  // 获取所有类型

foreach (var type in types)
{
    // 检查是否有 [TestClass] 特性
    if (type.GetCustomAttribute<TestClassAttribute>() != null)
    {
        var testMethods = type.GetMethods()
            .Where(m => m.GetCustomAttribute<TestMethodAttribute>() != null);
        
        // 找到了测试方法，记录下来
        foreach (var method in testMethods)
        {
            // 添加到测试执行队列
            testQueue.Add(() => {
                var instance = Activator.CreateInstance(type);
                method.Invoke(instance, null);
            });
        }
    }
}

// 执行所有发现的测试
foreach (var test in testQueue)
{
    test();
}
```

### 关键特性说明

| 特性 | 作用 | 执行时机 |
|------|------|----------|
| `[TestClass]` | 标记一个类是测试类 | 用于发现，不直接执行 |
| `[TestMethod]` | 标记一个方法是测试方法 | 在测试类实例化后执行 |
| `[AssemblyInitialize]` | 程序集级别初始化 | 所有测试执行前执行一次 |
| `[ClassInitialize]` | 类级别初始化 | 类中所有测试执行前执行一次 |
| `[TestInitialize]` | 方法级别初始化 | 每个测试方法执行前执行 |
| `[AssemblyCleanup]` | 程序集级别清理 | 所有测试执行后执行一次 |
| `[ClassCleanup]` | 类级别清理 | 类中所有测试执行后执行一次 |
| `[TestCleanup]` | 方法级别清理 | 每个测试方法执行后执行 |

### 为什么命名空间 `CfgCheck.Modules` 能被识别？

**命名空间不影响测试发现**。MSTest 会扫描整个程序集中的**所有类型**，无论命名空间是什么。只要：

- ✅ 类有 `[TestClass]` 特性
- ✅ 方法有 `[TestMethod]` 特性

就会被自动发现和执行。

### 项目结构示例

```
CfgValidator/
├── ConfigSetUp.cs          [TestClass] + [AssemblyInitialize]
├── Modules/
│   └── Test.cs            [TestClass] + [TestMethod]
└── output_code/           (Luban 生成的配置代码)
```

所有这些测试都会被 MSTest 自动发现和执行。

## 总结

### 关键要点

1. **项目类型**：MSTest 单元测试项目，通过 `dotnet test` 执行

2. **初始化机制**：
   - `[AssemblyInitialize]` 由 MSTest 自动调用
   - 在所有测试执行前执行一次
   - 用于加载配置等全局初始化工作

3. **LoadJson 方法**：
   - 用于从 `output_data` 目录加载 JSON 配置文件
   - 作为委托传递给 `cfg.Tables` 构造函数
   - 实现配置加载的解耦

4. **测试发现机制**：
   - 使用反射自动扫描程序集
   - 通过 `[TestClass]` 和 `[TestMethod]` 特性识别测试
   - 命名空间不影响测试发现

5. **执行顺序**：
   ```
   [AssemblyInitialize] 
   → [TestMethod] (所有测试方法)
   → [AssemblyCleanup]
   ```

### 相关文件

- `ConfigSetUp.cs` - 配置加载和程序集初始化
- `Modules/Test.cs` - 具体的测试用例
- `run_CfgValidator.bat` - 执行脚本（生成代码 + 运行测试）
- `CfgValidator.csproj` - 项目文件（包含 MSTest 依赖）
